# Statistical Taggers: HMMs, CRFs, and the Averaged Perceptron

## Motivation

A sequence tagger assigns a label to every token in a sequence: part-of-speech tags, chunk boundaries, named-entity spans, slot-filling categories in a dialogue system, edit operations in a diff. Before neural sequence labellers took over, this was the workhorse task of statistical NLP — and the classical models still ship in production, either as fallbacks, as fast paths, or as the label layer inside a neural pipeline.

This chapter builds up from Hidden Markov Models to linear-chain CRFs and averaged-perceptron taggers, focusing on the parts an engineer still needs to know: the algorithmic core (Viterbi), the feature design, and where the classical taggers still hold up.

## The three sequence tagger families

| Model                      | Type            | Decoding       | Notable strengths                                           |
|----------------------------|-----------------|----------------|-------------------------------------------------------------|
| Hidden Markov Model (HMM)  | Generative      | Viterbi        | Simple, works with tiny training data, closed-form training |
| Averaged Perceptron        | Discriminative  | Greedy / beam  | Fast, online-trainable, spaCy's classical tagger            |
| Conditional Random Field (CRF, linear-chain) | Discriminative | Viterbi | Best classical accuracy; global normalisation avoids label bias |

Neural sequence taggers (BiLSTM-CRF, transformer-CRF) are a strict superset of the same decoding machinery — they compute the transition/emission scores with a neural network but decode with Viterbi and a CRF layer. Understanding classical CRFs is a prerequisite for reading any modern NER paper.

## Hidden Markov Models

The HMM assumes the observed sequence `w = w₁ … w_T` is generated by an unobserved sequence of tags `t = t₁ … t_T`. Two independence assumptions:

- **Transition:** `P(tᵢ | t₁, …, tᵢ₋₁) ≈ P(tᵢ | tᵢ₋₁)` (first-order Markov).
- **Emission:** `P(wᵢ | t₁, …, t_T, w₁, …, wᵢ₋₁, wᵢ₊₁, …) ≈ P(wᵢ | tᵢ)`.

Joint probability factors:

```
P(w, t) = ∏ P(tᵢ | tᵢ₋₁) · P(wᵢ | tᵢ)
```

Training is closed-form MLE from counts on a labelled corpus (smoothing applies as in chapter 05). Decoding is the **Viterbi algorithm**: `O(T · |tags|²)` dynamic programming that finds `argmax_t P(w, t)`. Backward-pointer reconstruction yields the best tag sequence.

Reference: Lawrence Rabiner, ["A tutorial on hidden Markov models and selected applications in speech recognition"](https://web.ece.ucsb.edu/Faculty/Rabiner/ece259/Reprints/tutorial%20on%20hmm%20and%20applications.pdf), *Proceedings of the IEEE*, 1989. Still the definitive HMM reference.

HMMs are a poor fit for most modern tagging tasks because they cannot use arbitrary features of the observation — only the current token identity. But their algorithmic core (Viterbi) is exactly what CRFs and neural taggers still use.

## Maximum Entropy Markov Models and the "label bias" problem

The MEMM (McCallum, Freitag, Pereira, ["Maximum Entropy Markov Models for Information Extraction and Segmentation"](https://www.cs.umass.edu/~mccallum/papers/memm-icml2000.pdf), *ICML 2000*) replaces the HMM's generative emission with a discriminative per-position classifier: `P(tᵢ | tᵢ₋₁, features(w, i))`. This lets you use rich features (prefix, suffix, capitalisation, gazetteer membership) instead of just the token identity.

The failure of MEMMs — well documented in Lafferty, McCallum, Pereira ["Conditional Random Fields"](https://repository.upenn.edu/cgi/viewcontent.cgi?article=1162&context=cis_papers), *ICML 2001* — is the **label bias problem**: states with few outgoing transitions concentrate all probability mass on those transitions regardless of the observation. The next sequence of states can therefore ignore the observation entirely. This is the motivation for CRFs.

## Conditional Random Fields (linear-chain)

A linear-chain CRF models `P(t | w)` directly with a globally normalised distribution:

```
P(t | w) = (1/Z(w)) · exp( Σᵢ Σⱼ λⱼ · fⱼ(tᵢ₋₁, tᵢ, w, i) )
```

- `fⱼ` are feature functions on (previous tag, current tag, input, position).
- `Z(w)` is the partition function summed over all possible tag sequences.
- Training maximises log-likelihood on labelled data via L-BFGS (typical) or SGD.
- Decoding is Viterbi on the score matrix.

Because normalisation is over whole sequences, label bias disappears. Because the features are arbitrary, the model can exploit shape features (`^[A-Z][a-z]+$`), gazetteer hits, character prefixes/suffixes, previous-word features, and so on.

Reference implementations:

- **CRFsuite** (Naoaki Okazaki) — the classical C++ implementation, wrapped for Python as [`python-crfsuite`](https://github.com/scrapinghub/python-crfsuite) and [`sklearn-crfsuite`](https://sklearn-crfsuite.readthedocs.io/).
- **CRF++** — the historical reference implementation used in many NLP papers of the 2005-2015 era.
- **`pystruct`** — a Python library for general structured prediction (CRFs among other models); less maintained but pedagogically clear.

### Features that actually move a CRF

Classical NER feature templates (English):

```
w[i]                                   # current word (lowercased)
w[i-1], w[i+1]                         # neighbours
w[i].isupper(), w[i].istitle()         # shape flags
w[i][:3], w[i][-3:]                    # prefixes/suffixes
w[i].shape()                           # "Aaa", "aa", "999-99-9999", ...
POS[i], POS[i-1]                       # POS features from a prior tagger
gaz(w[i], "PERSON"), gaz(w[i], "ORG")  # gazetteer hits
prev_tag                               # from tᵢ₋₁ (structural)
BOS, EOS                               # positional markers
```

Two engineering rules:

- **Gazetteers matter.** A list of 20 000 company names as a boolean feature will beat a lot of clever architecture on ORG recall.
- **Log the top-weighted features** after training. Any high-weight nonsense feature (a URL fragment, a stray Unicode artefact) is a data-cleaning bug in disguise.

### Where linear-chain CRFs still ship

- **On-device NER, slot filling, PII redaction.** Kilobytes of weights, no GPU, no framework.
- **Regulated domains that must justify a prediction.** Every prediction is the sum of a small set of weighted features you can enumerate.
- **Tiny-data regimes** — a few thousand labelled sentences is a fine training set for a CRF; a neural NER is unstable at that scale.
- **CRF layer on top of a neural encoder.** BiLSTM-CRF (Lample et al., ["Neural Architectures for Named Entity Recognition"](https://arxiv.org/abs/1603.01360), NAACL 2016) and its transformer descendants still put a CRF layer on top of contextual embeddings for span-level structure. The Viterbi decoder from this chapter is the same one that runs there.

## The averaged perceptron

Michael Collins ("Discriminative Training Methods for Hidden Markov Models: Theory and Experiments with Perceptron Algorithms", *EMNLP 2002*) showed that a plain structured perceptron — take the highest-scoring tag sequence under the current weights, compare to gold, update on mismatches — could be trained quickly on a labelled corpus and give tagging accuracy competitive with more elaborate discriminative models. Averaging the weights across training epochs (Freund & Schapire's averaged perceptron trick) fixes the perceptron's tendency to overfit late-arriving examples.

This is spaCy's default classical POS tagger, and Textblob's, and the historical default in NLTK. It is:

- Faster to train than a CRF (single dot product per token per epoch).
- Slightly less accurate on the tail (no global normalisation).
- Trivial to update online with new examples.

Matthew Honnibal's ["A Good Part-of-Speech Tagger in about 200 Lines of Python"](https://explosion.ai/blog/part-of-speech-pos-tagger-in-python) is the readable reference; spaCy's `AveragedPerceptron` is essentially the same algorithm in Cython.

## What "state of the art" means today

For POS tagging and NER on Universal Dependencies / OntoNotes, transformer-based taggers (`stanza`, `flair`, HuggingFace token-classification heads) outperform classical CRFs by several F1 points. The gap is real and worth paying for in most greenfield systems.

The classical taggers still win on:

- **Latency budget.** A CRF or averaged perceptron runs at hundreds of thousands of tokens/sec on one CPU core. A transformer NER model runs at hundreds to thousands per core, or tens of thousands on a warm GPU.
- **Memory budget.** A CRF for CoNLL-2003 is a few megabytes; a fine-tuned BERT-base tagger is ~440 MB.
- **Domain drift** where you cannot afford to retrain a large model. Adding a hundred new gazetteer entries to a CRF is a config change; retraining a neural tagger is a project.
- **Determinism and auditability**, per chapter 01.

## Evaluating taggers correctly

- **Token-level accuracy** for POS tagging.
- **Span-level F1** for NER (`seqeval` library, using the standard BIO or BIOES tagset). Token-level accuracy on NER is a misleading metric because most tokens are `O`.
- **Confusion between related tag pairs** — `NN` vs `NNP`, `PER` vs `ORG` — is where most improvement lives.
- **Out-of-domain evaluation.** A CoNLL-trained NER model drops sharply on tweets, medical notes, and legal text. Always evaluate on a held-out slice of the domain that will actually see the model.

## Building a CRF NER in practice

```python
# sklearn-crfsuite: train a linear-chain CRF for CoNLL-style NER
import sklearn_crfsuite

def token_features(sent, i):
    tok = sent[i]
    features = {
        "bias": 1.0,
        "word.lower()": tok.lower(),
        "word[:3]": tok[:3],
        "word[-3:]": tok[-3:],
        "word.istitle()": tok.istitle(),
        "word.isupper()": tok.isupper(),
        "word.isdigit()": tok.isdigit(),
    }
    if i > 0:
        prev = sent[i - 1]
        features.update({"-1:word.lower()": prev.lower(), "-1:word.istitle()": prev.istitle()})
    else:
        features["BOS"] = True
    if i < len(sent) - 1:
        nxt = sent[i + 1]
        features.update({"+1:word.lower()": nxt.lower(), "+1:word.istitle()": nxt.istitle()})
    else:
        features["EOS"] = True
    return features

def sent_features(sent):
    return [token_features(sent, i) for i in range(len(sent))]

crf = sklearn_crfsuite.CRF(
    algorithm="lbfgs",
    c1=0.1,      # L1 regularisation
    c2=0.1,      # L2 regularisation
    max_iterations=100,
    all_possible_transitions=True,
)
crf.fit(X_train, y_train)   # X = [sent_features(s) for s in sents], y = tag sequences
```

This handful of features, plus a decent gazetteer, produces a competitive baseline on CoNLL-2003 English NER. Improvement from here typically comes from richer features (POS tags from a prior stage, character embeddings) or from replacing the CRF with a neural tagger.

## Chapter summary

- Sequence tagging is the classical NLP core: HMMs, MEMMs, CRFs, and averaged perceptrons all share the same Viterbi decoder.
- HMMs are simple but cannot use rich features; CRFs solve MEMM's label-bias problem via global normalisation and remain the strongest classical tagger.
- The averaged perceptron is spaCy's default classical POS tagger — fast, incrementally trainable, slightly less accurate than a CRF.
- Neural taggers beat classical ones on most benchmarks but classical taggers still win on latency, memory, cold-start, and audit.
- The Viterbi decoder and CRF loss you learn here reappear on top of every serious neural sequence-labelling model.
